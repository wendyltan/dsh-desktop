# DeepSeek Harness Desktop for macOS

> 让 Harness 在 Mac 上更像一款真正的应用：随手打开、快速提问，更新失败也不会弄坏原本能用的版本。

dsh-desktop 是 DeepSeek Harness 的第三方 macOS 客户端。它把常用入口收进菜单栏和本机窗口，并随应用安装一套保护机制，负责检查服务、更新 Harness 引擎，以及在异常时恢复到可用状态。

它与 DeepSeek 官方无隶属关系。目前项目面向愿意从源码构建的 macOS 用户，还没有签名公证的 DMG 安装包。

## 为什么做这个客户端

如果你每天都在用 Harness，大概会遇到这些时刻：网页突然打不开，不确定该刷新还是重启；看到新版本想升级，又担心升级后彻底不能用；临时有个问题，只想按一下快捷键问完就走。

dsh-desktop 想把这些事情变得简单一些：

- **一眼看懂现在能不能用**：先给结论，再告诉你影响和下一步，不用先读端口、进程和日志。
- **放心更新 Harness 引擎**：新版本会先在隔离环境里试运行，通过后才切换；失败就继续使用原来的版本。
- **出问题时有退路**：服务异常时可以检查并尝试恢复，也能恢复运行配置或切回保留的引擎版本。
- **少打断当前工作**：按 `⌥Space` 快速提问，可以新开会话，也可以延续最近的对话。

## 开始使用

### 准备环境

- macOS 13 或更高版本
- Xcode Command Line Tools
- 已经可以正常使用的 dsh / Harness 引擎和本机凭据

### 从源码安装

```bash
git clone https://github.com/wendyltan/dsh-desktop.git ~/.dsh/dsh-desktop
cd ~/.dsh/dsh-desktop
./build.sh
```

应用会安装到 `/Applications/DeepSeek Harness.app`。首次打开时，macOS 可能需要你右键应用并选择“打开”，确认运行这个本地签名的应用。

原生通知和快速提问需要额外安装桌面适配器：

```bash
node Scripts/install-bridge.mjs
```

适配器不可用时，相关交互会回到 Harness 网页，不会显示一个实际上没有完成的成功状态。

## 日常使用

### 菜单栏就是入口

鲸鱼图标常驻菜单栏，提供“打开客户端窗口”“快速提问”“当前状态”和“设置”等常用操作。你也可以让图标旁显示 DeepSeek 账户余额；余额低于自定义阈值时，文字会变红并发送提醒。

余额功能只在本机读取已有的 DeepSeek API Key，并请求 DeepSeek 官方余额接口。客户端不会保存、打印或展示密钥。

### 按一下快捷键，直接提问

快速提问默认使用 `⌥Space`。新会话可以选择模型和思考力度，不会打断当前会话；选择已有会话时，会延续最近的对话，并在面板中显示最新回复摘要。

快捷键、余额刷新间隔、预警阈值，以及快速提问的默认会话模式，都可以在“设置”（`⌘,`）中调整。

### 状态不再是一堆技术名词

“当前状态”会打开一个独立浮窗。顶部的“守护之环”用颜色和呼吸效果表示正常、处理中或异常；正常时，你先看到的是一句“运行状态正常”。

需要进一步排查时，再展开“详情与恢复”，查看桌面端、保护组件和 Harness 引擎版本，近期事件，以及可用的恢复操作。技术详情不会包含 API Key、提问内容或会话正文。

### 更新失败，不影响原来能用的版本

检查更新针对的是 **Harness 引擎**，不是 dsh-desktop 应用本身。一次更新会经历下载、隔离预检、切换和启动确认；任何一步失败，客户端都会继续保留此前可用的引擎。

如果新版引擎为本机 Web 开启了访问令牌，保护组件会在隔离预检和正式启动确认中使用该实例自己生成的令牌，不会再把正常的未授权响应误判成引擎损坏。令牌只会发送给同一个本地服务，故障摘要也会隐藏令牌内容。

更新成功后，你可以决定是否保留旧引擎。默认最多保留两个已验证版本，之后可在“管理引擎版本”中切换或删除。

### “恢复配置”和“切换版本”是两件事

- **恢复运行配置**：恢复 Web profile、桌面桥和已纳入保护的插件部署，不改变桌面应用、保护组件或 Harness 引擎版本。
- **切换引擎版本**：切换到本机已经保留并验证过的 Harness 引擎；切换前仍会做隔离检查，启动失败则回到当前版本。

执行恢复前，客户端会显示快照时间、包含内容和与当前配置的差异，避免一句模糊的“恢复到上一次”替你做决定。

## 和 dsh-ops-console 的关系

这两个项目可以配合使用，但彼此都不是对方的启动条件。

| 项目 | 负责什么 |
| --- | --- |
| dsh-desktop | Mac 本机客户端、快速提问、Harness 引擎更新、启动保护、恢复与回退 |
| [dsh-ops-console](https://github.com/wendyltan/dsh-ops-console) | 可选的远程访问插件，让手机或另一台电脑通过 Tailscale 安全打开 Harness |

不安装 dsh-ops，桌面端照常工作；不安装桌面端，dsh-ops 也能在 dsh Web 中管理远程入口，但它不会安装、更新、重启或恢复 Harness。

需要远程访问时，可以从 npm 安装：

```bash
dsh plugin --profile web add dsh-ops-console
```

## 开发与验证

```bash
./build.sh
./Scripts/verify.sh
```

构建产物只在本地生成，不应提交到仓库。`build.sh` 会校验桌面端与保护组件版本一致，组装并安装应用；`Scripts/verify.sh` 用于检查构建结果和关键约束。

Guardian 的集成验证同时覆盖无令牌的旧引擎和启用本地访问令牌的新引擎，包括同源限制、认证上下文传递和错误信息脱敏。
