# DeepSeek Harness Desktop for macOS

DeepSeek Harness 的 macOS 本机客户端：打开 Harness、安全更新 Harness 引擎，并由独立的桌面保护组件在异常时恢复服务。

这是独立开发的第三方客户端，与 DeepSeek 官方无隶属关系。

## 为什么需要它

网页服务、更新和本机设置出现问题时，用户最需要的是明确答案：

1. 现在能不能继续使用？
2. 如果不能，影响是什么？
3. 下一步按哪里？
4. 更新失败后，原来的可用状态是否还在？

dsh-desktop 的默认界面只回答这些问题。内部检查和恢复机制在后台工作；只有排障时才在技术详情中展示。桌面保护组件运行在 Harness 网页服务之外，可以独立完成启动检查、自动恢复和失败回退。

## 日常怎么用

菜单栏图标提供日常需要的主要入口：

- 打开客户端窗口
- 快速提问
- 当前状态
- 设置

“检查更新”和“设置”也位于标准 macOS 应用菜单中；客户端页面可使用网页自身的右键菜单重新加载。

菜单栏鲸鱼图标旁可显示 DeepSeek 账户余额（正常为系统文字色、低于预警阈值为红色），余额低于阈值时会发送低余额通知；也可以在设置中隐藏余额数字。余额功能只在本机读取现有 DeepSeek API Key，并请求 DeepSeek 官方余额接口，不保存、打印或展示密钥。

“当前状态…”会弹出独立的当前状态浮窗（无需先打开主窗口）：顶部是「守护之环」，用绿/蓝/红的呼吸光环直观表示服务健康（正常 / 处理中 / 异常）；正常时显示“运行状态正常”。展开「详情与恢复」可分别查看桌面端与保护组件版本、Harness 引擎版本、近期事件、运行配置快照和恢复操作。

如果暂时无法连接，点“检查并尝试恢复”。开始前会检查能否正常启动；如果无法完成，会继续保留此前能正常运行的状态。

快速提问（默认 ⌥Space）可选择「新会话」或「已有会话」：新会话会独立创建一个 Harness 会话，可指定模型和思考力度，不打断当前会话；已有会话会延续最近的对话，并在面板中显示最近一次回复摘要。

“设置…”（⌘,）里可自定义全局快捷键、余额刷新间隔与预警阈值，以及快速提问的默认模式、新会话模型和思考力度。

Harness 引擎更新会依次下载候选版本、检查能否启动、应用更新，并确认服务可用；它不会更新 dsh-desktop 应用本身。失败时会明确告诉你：此前能正常运行的版本仍在使用。更新成功后会询问是否保留旧 Harness 引擎，默认最多保留两个；已保留且通过验证的版本可在「管理引擎版本」中安全切换。

“恢复运行配置”只恢复 Web profile、桌面桥和已纳入保护的插件部署，不改变桌面端、保护组件或 Harness 引擎版本；恢复前会明确显示快照时间、包含内容及与当前配置的差异数量。

技术详情面向自行排障或技术支持，可能包含保护组件状态、最近操作和经过裁剪的错误信息；它不展示 API Key、提问内容或会话正文。

## dsh-ops 与本客户端

| 项目 | 面向用户的职责 |
| --- | --- |
| dsh-desktop | 本机打开 Harness、安全更新 Harness 引擎，并在异常时恢复服务可用性 |
| [dsh-ops-console](https://github.com/wendyltan/dsh-ops-console) | 可选的 Tailscale 远程访问插件：准备远程入口、显示访问状态并确认远程设备 |

两个项目互不作为启动条件：不安装 dsh-ops，桌面端仍能更新与恢复；不安装桌面端，dsh-ops 仍可在 dsh Web 中管理 Tailscale 远程入口，但不负责启动、更新或恢复 Harness。

需要远程访问时，可从 npm 安装 dsh-ops：

    dsh plugin --profile web add dsh-ops-console

## 安装

目前通过源码构建安装。需要 macOS 13+、Xcode Command Line Tools，以及已经可以使用的 dsh/Harness 引擎和本机凭据配置。

    git clone https://github.com/wendyltan/dsh-desktop.git ~/.dsh/dsh-desktop
    cd ~/.dsh/dsh-desktop
    ./build.sh

应用会安装到 `/Applications/DeepSeek Harness.app`。首次打开时，macOS 可能要求通过右键“打开”确认本地签名应用。

可选的原生通知与快速提问需要显式安装适配器：

    node Scripts/install-bridge.mjs

适配器不可用时，交互会回到 Harness 网页，不会假装已完成。

## 开发与验证

    ./build.sh
    ./Scripts/verify.sh

`dsh-desktop` 独立负责客户端窗口、菜单、更新和服务恢复；`dsh-ops-console` 是可选的浏览器/手机运行台，不是桌面端的启动依赖。默认界面优先展示“当前能不能用、影响是什么、下一步按哪里”，内部状态只在技术详情中展开。

构建产物只在本地生成，不应提交到仓库；安装后的应用位于 `/Applications/DeepSeek Harness.app`。
